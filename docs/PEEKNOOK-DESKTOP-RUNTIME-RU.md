# Безопасный запуск PeekNook Desktop

Установленное desktop-приложение состоит из интерфейса Tauri/React, локального Python API, фонового worker и SurrealDB. В production Tauri выбирает отдельные свободные порты для API и базы, запускает их только на `127.0.0.1` и сообщает интерфейсу точный адрес API через внутреннюю IPC-команду.

При каждом запуске Tauri создаёт новый случайный токен. Этот токен передаётся Python sidecar через окружение и доступен интерфейсу только через внутреннюю Tauri-команду. Без правильного токена локальный API возвращает `401`.

Фоновый worker запускается из того же frozen-бинарника и не требует установленного Python или `uv`. Он обрабатывает очередь импорта источников, эмбеддингов и подкаст-задач.

При обычном выходе Tauri завершает всё дерево запущенных им процессов: загрузчик PyInstaller, API, worker и SurrealDB. Новый запуск выбирает новые порты и токен, поэтому старый порт не блокирует приложение.

Скрипт `scripts/build-backend.sh` после PyInstaller обязательно запускает frozen-бинарник с `--self-test` из пустой временной папки. Сборка останавливается, если внутри sidecar отсутствует Python-модуль, нативная библиотека, конфигурация или шаблон. На Windows скрипт отдельно обрабатывает расширение `.exe`.

API по умолчанию принимает браузерные запросы только от локальных Vite/legacy-интерфейсов и Tauri origins. Для отдельного web-интерфейса необходимо явно задать `CORS_ORIGINS`.

До готовности `/health` пользователь видит экран запуска. Первый запуск может быть дольше обычного, потому что PeekNook подготавливает локальную базу и фоновые сервисы. Через 120 секунд без успешного ответа показывается диагностическая ошибка.

## Важные границы

- Механизм защищает локальный API от произвольных сайтов, но не заменяет шифрование документов на диске.
- Он не является облачной авторизацией и не реализует end-to-end sync encryption.
- Локальный arm64 `.app` проверен целиком, но публичный релиз всё ещё требует подписанных `.dmg`, `.exe` и `.msi`, notarization macOS и проверки updater-подписи.
- Для Windows x64 sidecar скачивает бинарник из [официального релиза SurrealDB v2.3.7](https://github.com/surrealdb/surrealdb/releases/tag/v2.3.7), проверяет закреплённый SHA-256 и только затем атомарно устанавливает `surreal.exe` в каталог приложения. Этот путь покрыт тестами и Windows CI smoke, но результат следующего запуска Windows runner ещё должен быть подтверждён.
- SurrealDB `v2.3.7` не публикует отдельный Windows ARM64-бинарник. PeekNook останавливается с понятной ошибкой вместо неподтверждённого запуска через эмуляцию.

## Контроль обновления SurrealDB

Версия по умолчанию закреплена вместе с SHA-256 для macOS, Linux и Windows x64. Если оператор намеренно задаёт другую `PEEKNOOK_SURREAL_VERSION`, он обязан также задать официальный `PEEKNOOK_SURREAL_SHA256`. Архив с неправильным хешем не заменит уже установленную базу.

Windows CI запускает `scripts/peeknook-windows-runtime-smoke.ps1`: проверяет настоящий frozen-sidecar, `/health`, обязательный токен, CORS, запуск worker, официальный SHA-256 SurrealDB и освобождение портов после остановки.
